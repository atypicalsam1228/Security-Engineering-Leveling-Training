# Platform build brief: the in-lab services

Goal: after `lab up` finishes the OpenShift install, `lab platform` (also run by `lab up`) installs the services every module assumes, so a learner on their own laptop gets them with no manual steps. Your `<area>` is `git-chat`, `siem` or `security` (see Owners). Read `LAB-CONTRACT.md` first (namespaces, pinned versions, variables), then `lab/platform/README.md`, `lab/platform/install.sh`, `lab/platform/lib.sh` and `lab/platform/05-trust.sh`.

## How it runs

- `lab/platform/NN-name.sh`, run in file-name order by `install.sh`, inside the tools container (oc, kubectl, helm 3.22.1, jq, curl, openssl, python3 3.9; `terraform` and `aws` exist but you rarely need them). `KUBECONFIG` is set; you are cluster-admin; lab variables from `/workspace/.lab/lab.env` are in the environment; use `lab_var NAME` for a value written earlier in the same run.
- Every script is idempotent (safe to run twice, skips finished work), waits until what it installed is ready (`wait_until`, `wait_rollout`, with a timeout and a clear `die` message), and prints one short line per milestone with `say`. Strict mode (`set -euo pipefail`), `. "$(dirname "$0")/lib.sh"`.
- Allowed commands: those in `generators/checks/commands.txt` plus `helm`, `oc`, `kubectl`, `mktemp`, `mv`, `base64`, `sed`. Quote everything. Never print a secret.
- Variables the platform issues must be saved with `lab_var_set NAME VALUE` (written to lab.env mode 600, then visible in every `lab shell`). Passwords already generated by `lab up`: `KEYCLOAK_ADMIN_PASSWORD`, `GRAFANA_PASSWORD`, `LOKI_PASSWORD` (read them with `require_var`). Everything else you create yourself with `random_secret`.
- Variables to set (names exactly as in the contract): `GITEA_URL` (https route), `GITEA_INTERNAL_URL` (`http://<service>.gitea.svc.cluster.local:3000`), `GITEA_USER`, `GITEA_TOKEN`, `MM_URL`, `MM_WEBHOOK_URL`, `LOKI_URL`, `LOKI_USER`, `LOKI_PASSWORD` (existing), `GRAFANA_URL`, `GRAFANA_USER` (`admin`), `KEYCLOAK_URL`, `KEYCLOAK_ADMIN_USER`, `ARGOCD_URL`. `LOKI_CA_FILE` is already set by `05-trust.sh` (the ingress CA); all services are exposed as OpenShift Routes with edge TLS using the default ingress certificate, so that one CA covers them all.
- Footprint: one single-node cluster with the estimates in `terraform/README.md` (about 28 to 32 GiB total in use). Give every workload small requests and sensible limits, use one replica, and use the cluster default StorageClass for PVCs (gp3-csi).
- FIPS mode is on: do not use images or tools that need non-FIPS crypto in the pod; prefer Red Hat or vendor images that run under an arbitrary UID (OpenShift `restricted-v2` SCC). Do not grant `anyuid` or `privileged` unless the tool cannot run without it (Falco and the Trivy operator may need more; say why in a comment).
- Pin every image tag, chart version and operator channel to a version you have verified exists (registry manifest API with curl, or the chart repo `index.yaml`). Put each pin in a variable at the top of its script, and list it in your own file `lab/platform/versions-<area>.txt` (one row: component, version, where verified, date). Do not guess a tag.

## What exists already (do not duplicate)

- Start states install, per module and when missing: OpenShift Pipelines operator (`ensure_operator`), the Logging collector / ClusterLogForwarder named `siem-forwarder` (`ensure_siem_forwarder`), Compliance Operator, Service Mesh 3, and the `alloy` Deployment for SDR-4 (check `lab/states/sdr-4/10-alloy.sh`). You build what they point at: Loki and Grafana for the forwarder and Alloy; the Pipelines operator is also installed here so ENG-0's health check passes before any module.
- The bastion save script (`terraform/templates/bastion-userdata.sh.tftpl`) expects a pod labelled `app=gitea` in namespace `gitea`, a secret `gitea-admin` with keys `username` and `password`, repositories at `/data/git/gitea-repositories/<owner>/<repo>.git`, and `curl`/`git` inside the pod. Match that.
- `lab/states/_common/lib.sh` (`gitea_call`, `gitea_ensure_repo`, `loki_get`, `grafana_get`, ...) and the module start states show exactly which API calls, paths, secret and service names each module uses. Before you write a component, grep `lab/states`, `generators/content` and `lab/states/*/TODO.md` for it and match every name and behaviour they rely on. Where a start state's assumption is wrong or impossible, fix the start state, not the other way round, and list it in your report.
- ENG-0's health check (`lab/states/eng-0/30-sandbox-repo.sh`) expects pods: Loki and Grafana in `siem` (pod names containing `loki`, `grafana`), any pod in `chat`, `gitea` and `kyverno`, `tekton-pipelines` in `openshift-pipelines`, `trivy` and `falco` in `security-tools`, `siem-forwarder` or `collector` in `openshift-logging`.

## Do not

- Edit `generators/`, `modules/`, module content, `lab/labcli/`, `lab/image/`, `terraform/`, `LAB-CONTRACT.md`, or other agents' scripts. Shared helpers you need beyond `lib.sh`: add to your own script, or ask in your report.
- Hardcode passwords, tokens or default credentials. Generate them or read them from lab.env.
- Use `-k` / `--insecure` for calls to Routes: use `--cacert "$(lab_var LOKI_CA_FILE)"` (the ingress CA) or the in-cluster HTTP service.
- Leave a TODO that says "assumed". If you cannot verify a flag, an API path or an image, read the vendor docs / source (WebFetch, Context7) until you can, and cite the source in a comment on the line.

## Finish

`bash -n` every script; run `shellcheck` if present. Write `lab/platform/notes-<area>.md` for your scripts (what each does, which variables it saves, its resource requests, anything unverified). Do not edit `lab/platform/README.md`; other agents work in parallel. Final report under 200 words: scripts written, pins verified (component, version, how), variables saved, start-state changes, unverified items.
